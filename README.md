## Controle de versão, colaboração e desenvolvimento profissional

Bem vindo ao repositório do curso de Git e GitHub.

## Por que aprender Git?

Durante o desenvolvimento de um projeto, os arquivos passam por diversas alterações.

Sem um sistema de controle de versão, é comum encontrar pastas como:

```text
Projeto final

Projeto final corrigido

Projeto final novo

Projeto final agora funciona

Projeto final definitivo
```

Esse tipo de organização dificulta a identificação da versão correta e aumenta o risco de perder alterações importantes.

Com o Git, eu consigo registrar a evolução do projeto por meio de commits.

Cada commit informa:

1. O que foi alterado.

2. Quem realizou a alteração.

3. Quando a alteração aconteceu.

4. Qual era o estado anterior.

5. Por que a mudança foi necessária.

6. Como retornar a uma versão anterior.

O Git transforma o histórico do projeto em uma sequência organizada e compreensível.

## Por que utilizar o GitHub?

O Git funciona no computador e registra as versões localmente.

O GitHub permite publicar esses repositórios na internet e acrescenta recursos de colaboração.

Com o GitHub, podemos:

1. Armazenar projetos remotamente.

2. Compartilhar códigos e documentos.

3. Trabalhar em equipe.

4. Criar branches.

5. Abrir Pull Requests.

6. Revisar alterações.

7. Registrar tarefas com Issues.

8. Organizar atividades com Projects.

9. Criar tags e releases.

10. Automatizar verificações.

11. Publicar sites com GitHub Pages.

12. Construir um portfólio profissional.

## Boas práticas que serão reforçadas

1. Não trabalhar diretamente na branch principal quando houver uma tarefa separada.

2. Não publicar senhas, tokens ou chaves privadas.

3. Não criar commits com mensagens genéricas.

4. Não utilizar comandos destrutivos sem compreender o resultado.

5. Atualizar o projeto antes de iniciar uma nova tarefa.

6. Criar commits pequenos e relacionados.

7. Revisar as alterações antes de publicar.

8. Manter a documentação atualizada.

9. Excluir branches concluídas somente depois da confirmação da integração.

10. Comunicar decisões importantes à equipe.
